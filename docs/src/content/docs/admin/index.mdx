As an administrator, you decide what labelers read, what they answer, and what the finished
dataset contains. You describe those decisions in a `.jsonc` configuration file. A schema
is simply the definition of those fields: their names, value types, and rules.

## Choose what labelers will see

Start with the question you need answered. These are actual MLabel controls; each link shows the configuration that creates it.

## Start from a working example

The [illustrated cookbook](/config/cookbook/) pairs every recipe with screenshots, a downloadable configuration, and sample data. Choose a recipe for multiple answers, reviewer details, source tables, warning rules, or another common task.

## Build your first project

[Create a small working project →](/admin/first-project/)

The tutorial includes a complete configuration and sample CSV. You will copy a record ID,
ask for a decision, add optional notes, and check the export.

## Design and launch

1. [Plan the output](/admin/planning/): define what each column means and which answers are required.
2. [Choose field types and controls](/config/widgets/): see what labelers will actually use.
3. [Add clear captions and help](/config/display/) and [arrange fields into cards](/config/cards/).
4. [Validate the configuration](/config/#check-your-work), then pilot it on representative records.
5. [Distribute the app and configuration](/admin/deploying/) and hand the data to a [preparer](/preparers/).
